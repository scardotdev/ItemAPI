# Security Policy

## Supported versions

Security fixes are provided for the latest released version of ItemAPI. Older
versions may be asked to upgrade before a fix is evaluated or released.

| Version | Supported |
| --- | --- |
| 1.2.x | Yes |
| < 1.2 | No |

## Reporting a vulnerability

Do **not** disclose suspected vulnerabilities in a public issue, discussion,
pull request, server log, or chat channel.

Use GitHub's private vulnerability reporting flow for this repository: open the
repository's **Security** tab, choose **Advisories**, and select **Report a
vulnerability**. If that option is not available, contact the maintainer
privately through the contact options on the repository owner's GitHub profile
and ask for a secure reporting channel. Do not send exploit details through a
public channel.

Include, when possible:

- the affected ItemAPI and server framework versions;
- impact and realistic attack scenario;
- configuration and environmental prerequisites;
- minimal reproduction steps or proof of concept;
- relevant logs with credentials, tokens, IP addresses, and personal data
  removed; and
- any suggested mitigation or disclosure deadline.

The maintainer will aim to acknowledge a report within 7 days, provide an
initial assessment within 14 days, and share progress as remediation proceeds.
These are targets rather than guarantees. Please allow a reasonable remediation
window before disclosure and coordinate publication with the maintainer.

Good-faith research that avoids privacy violations, data destruction, service
disruption, and access beyond what is necessary to demonstrate the issue is
welcome. This policy does not authorize testing systems or third-party endpoints
you do not own or have explicit permission to test.
